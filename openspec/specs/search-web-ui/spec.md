# search-web-ui Specification

## Purpose

Определяет поведение веб-интерфейса, через который пользователь описывает вопрос своими словами, запускает поиск и изучает найденные локальные и внешние совпадения вместе со сгенерированным ответом.

## Requirements

### Requirement: Форма поиска по описанию вопроса
Веб-интерфейс SHALL предоставлять форму ввода текстового описания вопроса с возможностью задать число результатов и минимальный порог похожести, а также MUST блокировать отправку запроса при пустом или слишком коротком описании.

#### Scenario: Отправка корректного описания
- **WHEN** пользователь вводит описание вопроса и запускает поиск
- **THEN** интерфейс отправляет запрос и переходит в состояние выполнения операции

#### Scenario: Пустое описание
- **WHEN** пользователь пытается запустить поиск с пустым описанием
- **THEN** интерфейс не отправляет запрос и показывает подсказку о необходимости ввести описание

#### Scenario: Изменение параметров поиска
- **WHEN** пользователь изменяет число результатов или порог похожести
- **THEN** интерфейс применяет новые значения к следующему запросу поиска

### Requirement: Отображение состояния выполнения
Веб-интерфейс SHALL отображать состояние выполнения поиска, различая как минимум состояние ожидания, выполнения, успешного завершения и завершения с ошибкой или с частичными результатами.

#### Scenario: Длительный поиск
- **WHEN** поиск выполняется дольше нескольких секунд
- **THEN** интерфейс показывает индикатор выполнения и остаётся отзывчивым для пользователя

#### Scenario: Частичные результаты
- **WHEN** поиск завершён, но один из источников недоступен
- **THEN** интерфейс показывает полученные совпадения вместе с явным предупреждением о недоступном источнике

#### Scenario: Внешний источник не нашёл совпадений
- **WHEN** внешний источник ответил успешно, но без совпадений
- **THEN** интерфейс сообщает, что внешний поиск не дал результатов, и не показывает это как ошибку источника

#### Scenario: Внешний поиск искал по сокращённому запросу
- **WHEN** описание вопроса было длиннее 50 символов и внешний источник получил сокращённый запрос
- **THEN** интерфейс явно показывает, по какому запросу искал внешний источник, чтобы пользователь понимал причину возможных расхождений с локальной выдачей

#### Scenario: Внешний источник отверг запрос
- **WHEN** внешний источник вернул ответ без блока результатов
- **THEN** интерфейс показывает это как проблему внешнего поиска, а не как отсутствие совпадений

#### Scenario: Ошибка поиска
- **WHEN** поиск завершился ошибкой
- **THEN** интерфейс показывает понятное сообщение об ошибке и идентификатор запроса, позволяя повторить поиск

### Requirement: Представление результатов поиска
Веб-интерфейс SHALL отображать для каждого совпадения текст вопроса, ответ, источник и оценку похожести, а также SHALL разделять или явно помечать результаты, полученные из локальной базы и из внешнего источника. Подпись оценки SHALL соответствовать величине, которой она является, и MUST NOT называть ранговую, позиционную или нормированную по списку величину семантической близостью.

#### Scenario: Список совпадений
- **WHEN** поиск вернул совпадения
- **THEN** интерфейс показывает упорядоченный по убыванию похожести список с источником и оценкой для каждого совпадения

#### Scenario: Отсутствие совпадений
- **WHEN** поиск не вернул ни одного совпадения
- **THEN** интерфейс показывает явное сообщение об отсутствии результатов и предлагает изменить формулировку или порог

#### Scenario: Переход к внешнему источнику
- **WHEN** совпадение получено из внешнего источника и имеет доступную ссылку на страницу вопроса
- **THEN** интерфейс предоставляет возможность открыть эту страницу

#### Scenario: Честная подпись оценки
- **WHEN** совпадение отображается с оценкой похожести
- **THEN** подпись оценки отражает единую величину близости, по которой ранжируются оба источника, и не выдаёт за неё позицию в списке или нормированный ранг

#### Scenario: Совпадение из двух источников
- **WHEN** один и тот же вопрос найден и в локальной базе, и во внешнем источнике
- **THEN** интерфейс показывает одно совпадение с указанием обоих источников и единой оценкой

### Requirement: Отображение сгенерированного ответа
Веб-интерфейс SHALL отображать сгенерированный ответ отдельно от списка совпадений, показывая, на какие найденные вопросы он опирается, и MUST NOT показывать ответ как достоверный при отсутствии подтверждающих совпадений.

#### Scenario: Ответ сформирован
- **WHEN** поиск вернул совпадения и сгенерированный ответ получен
- **THEN** интерфейс показывает ответ вместе со ссылками на использованные совпадения

#### Scenario: Генерация недоступна
- **WHEN** генерация ответа завершилась ошибкой или недоступна
- **THEN** интерфейс показывает совпадения и сообщает, что сгенерированный ответ получить не удалось

### Requirement: Размещение веб-интерфейса
Веб-интерфейс SHALL быть смонтирован в тот же ASGI-процесс, что и API, по пути `/ui` и MUST обращаться к API внутрипроцессно, без отдельного сервера и без указания адреса API в настройках.

#### Scenario: Открытие интерфейса
- **WHEN** сервис запущен командой `chgk-serve`
- **THEN** интерфейс доступен по `/ui`, а документация API — по `/docs`, и оба пути ведут в один процесс

#### Scenario: Пути API вне префикса интерфейса
- **WHEN** интерфейс смонтирован
- **THEN** эндпоинты API доступны по путям `/search`, `/imports`, `/healthz`, `/readyz` без префикса `/ui`

#### Scenario: Интерфейс не попадает в схему API
- **WHEN** клиент запрашивает схему OpenAPI
- **THEN** пути веб-интерфейса в неё не входят, а эндпоинты API описаны отдельно от страниц `/ui`
