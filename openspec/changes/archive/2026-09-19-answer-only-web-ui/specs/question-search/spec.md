## MODIFIED Requirements

### Requirement: Формирование ответа на основе найденных вопросов
Система SHALL по запросу формировать ответ на естественном языке на исходное описание вопроса, используя chat-модель GigaChat через интеграцию `langchain_gigachat`, и SHALL передавать найденные похожие вопросы как необязательный контекст, который MAY быть пустым. Система MUST NOT отказываться от генерации из-за отсутствия подтверждающих совпадений.

#### Scenario: Успешная генерация ответа
- **WHEN** поиск вернул совпадения и запрошено формирование ответа
- **THEN** система возвращает сгенерированный ответ вместе со ссылками на использованные совпадения

#### Scenario: Нет подтверждающих совпадений
- **WHEN** совпадения отсутствуют, а формирование ответа запрошено
- **THEN** система генерирует ответ на исходный вопрос с пустым списком похожих вопросов

#### Scenario: Ошибка GigaChat при генерации
- **WHEN** GigaChat недоступен или возвращает ошибку во время генерации
- **THEN** система возвращает найденные совпадения и признак недоступности генерации ответа вместо ошибки всего запроса

#### Scenario: Запуск генерации без совпадений
- **WHEN** ни один вопрос не прошёл порог похожести
- **THEN** граф поиска всё равно вызывает генерацию ответа

### Requirement: Оценка похожести и пояснение
Каждое совпадение SHALL нести оценку `score` и признак `score_kind`, указывающий происхождение совпадения и использованный лексический сигнал, и MUST NOT выдавать ранговую или позиционную величину за семантическую близость. Оценка SHALL быть одной и той же величиной для обоих источников, а порог из настроек SHALL сравниваться именно с ней. Значение порога по умолчанию SHALL быть `0.85`: порог отбирает контекст для генерации, а не наличие ответа.

#### Scenario: Фильтрация по порогу
- **WHEN** из настроек задан минимальный порог похожести
- **THEN** в ответе остаются только совпадения с оценкой не ниже порога

#### Scenario: Оценки из разных источников
- **WHEN** совпадения получены из локальной базы и из внешнего источника
- **THEN** обе оценки выражают одну и ту же величину близости, а происхождение совпадения и вклад лексического сигнала виден в API

#### Scenario: Понижение порога не меняет порядок
- **WHEN** порог понижен
- **THEN** к уже найденным совпадениям добавляются совпадения с более низкой оценкой, а порядок остальных не меняется

#### Scenario: Порог по умолчанию отсекает несвязанные вопросы
- **WHEN** порог похожести не задан явно
- **THEN** применяется значение `0.85`, отсекающее совпадения ниже шумового пола близости
