## Why

Короткий поисковый запрос к gotquestions.online строится без знания о корпусе: отбор терминов идёт по длине слова и заглавной букве, поэтому в запрос попадают мусорные слова («необходимости», «только», «мученики») и внешний сайт получает худший запрос, чем мог бы. Для описания про «мучеников» уходило три запроса, потому что усечённый по длине список терминов разбивался на три куска по 50 символов, а бюджет запросов никто не задавал осмысленно. Хуже того, сайт считает слова запроса конъюнкцией: проверка на живом сайте показала, что запрос из пяти редких терминов возвращает ноль карточек, тогда как один термин «мучеников» — пять.

Лексический индекс BM25 строится лениво внутри локальной ветки поиска, поэтому информативность терминов (IDF по локальному корпусу) в момент построения внешнего запроса недоступна: внешняя ветка стартует параллельно и про индекс не знает. Из-за этого же холодный запрос платит за построение индекса полностью, а любая попытка дождаться индекса из внешней ветки поставила бы её в зависимость от чужой ветки и её таймаута.

## What Changes

- В граф добавляется нода `ensure_corpus_index`, которая строит лексический индекс по локальному корпусу до ветвления и кладёт в состояние информативность терминов описания (IDF по стемам).
- Нода выполняется параллельно с вычислением эмбеддинга описания: построение индекса уезжает под уже существующую задержку, а не добавляется к ней.
- У ноды собственный таймаут и собственный обработчик ошибок: недоступность базы не вешает внешнюю ветку, а лишь лишает её взвешивания по редкости.
- Внешний источник получает несколько коротких запросов, каждый — ровно из одного самого редкого термина описания, а не из самых длинных слов; фильтр стоп-слов и типовых формулировок остаётся перед отбором.
- Число коротких запросов ограничивается настройкой (по умолчанию 3), а прежние многотёрмовые куски по 50 символов уходят: они сужали выдачу до пустой.
- Локальная ветка перестаёт быть владельцем индекса: она читает готовый кэш, а ленивое построение остаётся только запасным путём для оценочной утилиты и тестов.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `question-search`: короткий запрос к внешнему источнику формируется из самых редких терминов по локальному корпусу и отправляется одним запросом; появляется требование готовности лексического индекса до ветвления поиска.
- `service-observability`: добавляется учёт сборки лексического индекса и причины, по которой информативность терминов оказалась недоступна.

## Impact

- `src/chgk_agent/search/graph.py` — новая нода на критическом пути перед ветвлением.
- `src/chgk_agent/search/nodes.py` — узел готовности индекса, передача информативности терминов во внешнюю ветку.
- `src/chgk_agent/search/local.py` — чтение готового индекса вместо владения им.
- `src/chgk_agent/search/lexical.py` — доступ к документной частоте для расчёта информативности терминов описания.
- `src/chgk_agent/external/query.py` — отбор терминов по редкости, короткие запросы по одному термину с бюджетом настройкой.
- `src/chgk_agent/external/gotquestions.py` и `src/chgk_agent/external/base.py` — приём информативности терминов в вызове поиска.
- `src/chgk_agent/config.py` — настройки таймаута сборки индекса и числа коротких запросов.
- `src/chgk_agent/observability/metrics.py` — метрики сборки индекса и недоступности информативности.
- `tests/test_external_query.py`, `tests/test_search_graph.py`, `tests/test_lexical.py` — тесты отбора терминов, ноды и запасного пути.
- `README.md` — описание порядка работы с индексом, если он изменится для эксплуатации.
