## Why

Интеграционные тесты по умолчанию подключаются к рабочей базе `chgk_agent`: фикстуры создают движок из `Settings(_env_file=None)`, то есть из того же DSN, что и сервис. Из-за этого тестовые импорты совпадают по `text_hash` с реально загруженными вопросами, переиспользуют существующие строки и перезаписывают их настоящие векторы эмбеддингами тестовых заглушек. Инцидент уже произошёл: вопрос «про порох в пороховнице» получил вектор модели `VocabularyEmbeddings`, и каждый полный прогон `pytest` повторяет порчу данных.

## What Changes

- Появляется отдельная база для интеграционных тестов; рабочая база в тестах не используется и не изменяется.
- Адрес тестовой базы задаётся настройкой `CHGK_DATABASE__TEST_DSN`, по умолчанию — тот же сервер, но имя базы с суффиксом `_test`.
- Тестовая база создаётся автоматически при первом запуске и приводится к актуальной схеме миграциями Alembic.
- Добавляется защита: если адрес тестовой базы совпадает с рабочей, тесты падают с понятной ошибкой, а не портят данные.
- Если тестовую базу нельзя создать или к ней нет доступа, интеграционные тесты пропускаются, как и раньше.
- Устраняется последствие прошлой порчи: повреждённый вектор пересчитывается командой переиндексации.

## Capabilities

### New Capabilities
- `test-database-isolation`: правила запуска интеграционных тестов на отдельной базе — выбор адреса, автоматическая подготовка схемы, защита рабочей базы и деградация до пропуска тестов, когда тестовая база недоступна.

## Impact

- **Код**: `tests/conftest.py` (фикстуры движка и сессии), новый вспомогательный модуль подготовки тестовой базы, `tests/test_embedding_model_change.py` (тест миграции создаёт временную базу), `src/chgk_agent/config.py` (настройка тестового DSN).
- **Инфраструктура**: локальный PostgreSQL с pgvector; для автоматического создания базы нужны права `CREATEDB`, иначе требуется создать базу вручную.
- **Документация**: README и `.env.example` описывают тестовый DSN и требования к окружению.
- **Данные**: один вопрос в рабочей базе имеет вектор тестовой модели и требует переиндексации; новых изменений рабочей базы тестами после правки не будет.
- **Совместимость**: команды запуска тестов и маркер `integration` не меняются, поэтому привычный `uv run pytest -q` продолжает работать.
