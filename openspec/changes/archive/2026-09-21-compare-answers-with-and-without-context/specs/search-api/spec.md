## MODIFIED Requirements

### Requirement: Эндпоинт поиска
Система SHALL предоставлять асинхронный HTTP-эндпоинт поиска, принимающий описание вопроса и параметры поиска и возвращающий совпадения в структурированном виде с указанием источников, оценок похожести и статуса каждого источника, причём статус SHALL различать непустую выдачу, пустую выдачу, отвергнутый запрос и недоступность источника. Ответ SHALL содержать два отдельных результата генерации в явно названных полях: ответ без подгрузки похожих вопросов и ответ с подгрузкой. Поле с единственным ответом сохраняться MUST NOT, чтобы клиент не мог принять один прогон за другой. Запрос SHALL NOT принимать признак, отключающий генерацию ответа, и MUST отклонять запрос с таким полем как содержащий неизвестное поле.

#### Scenario: Успешный запрос поиска
- **WHEN** клиент отправляет корректный JSON-запрос поиска
- **THEN** сервис отвечает кодом 200 и структурированным результатом, содержащим объединённые совпадения и статусы источников

#### Scenario: Два ответа в одном ответе сервиса
- **WHEN** поиск вернул совпадения
- **THEN** сервис возвращает в ответе оба результата генерации: без подгрузки похожих вопросов и с подгрузкой, не сводя их к одному полю

#### Scenario: Ответ без подгрузки отсутствует
- **WHEN** совпадений выше порога не нашлось
- **THEN** сервис возвращает результат генерации без подгрузки, а поле ответа с подгрузкой остаётся пустым, а не заполняется тем же текстом

#### Scenario: Частичный отказ генерации
- **WHEN** один из двух прогонов генерации завершился ошибкой, а другой успешно
- **THEN** сервис отвечает кодом 200, возвращает успешный ответ и признак недоступности для неуспешного прогона отдельно

#### Scenario: Признак отключения генерации не принимается
- **WHEN** клиент отправляет запрос с полем, отключающим генерацию ответа
- **THEN** сервис отвечает кодом 422 и не выполняет поиск

#### Scenario: Некорректный запрос
- **WHEN** запрос не проходит валидацию схемы, например отсутствует описание вопроса или указан недопустимый порог
- **THEN** сервис отвечает кодом 422 с описанием полей, вызвавших ошибку валидации

#### Scenario: Ограничение размера входного описания
- **WHEN** описание вопроса превышает максимально допустимую длину
- **THEN** сервис отклоняет запрос с ошибкой валидации и не обращается к GigaChat или внешнему источнику

#### Scenario: Отвергнутый запрос внешнего источника
- **WHEN** внешний источник вернул страницу без блока результатов и без признака отсутствия совпадений
- **THEN** сервис отвечает кодом 200 и передаёт для этого источника статус отвергнутого запроса, а не пустой выдачи
