## Why

Сервис отвечает на вопрос игрока одной сгенерированной репликой, но по ответу нельзя понять, помог ли поиск по базам вопросов: модель могла знать ответ и без подсказок, а могла опереться на найденные похожие вопросы. Без сравнения нельзя ни оценить пользу поиска, ни заметить, когда подгрузка контекста уводит модель в сторону.

## What Changes

- На каждый запрос выполняются два независимых прогона генерации: ответ без подгрузки похожих вопросов и ответ с подгрузкой. Оба возвращаются клиенту и показываются рядом, поэтому видно, изменился ли ответ благодаря поиску.
- Прогон без подгрузки стартует сразу после разбора запроса, одновременно с подготовкой к поиску: он не зависит от результатов поиска, а последовательный запуск удлинил бы ответ на длительность первого вызова модели.
- Ответ с подгрузкой использует найденные совпадения как необязательный контекст, как и раньше; если выше порога ничего не нашлось, сравнивать не с чем, поэтому возвращается только один ответ без подгрузки.
- Веб-интерфейс показывает два ответа рядом с подписями «Без базы вопросов» и «С учётом базы вопросов» вместо одного ответа. Каждый ответ независим: недоступность одного прогона показывается «Не знаю» на его месте и не отменяет второй.
- Генерация становится безусловной: признак `generate_answer` уходит из запроса API, настроек, состояния графа и клиента интерфейса вместе с развилкой, которая позволяла пропустить генерацию. Ответ на вопрос нужен всегда, а флаг только удваивал число путей исполнения.
- **BREAKING**: в ответе API поле `answer` заменяется двумя полями — `answer_without_context` и `answer_with_context`, чтобы клиент не догадывался, какой именно прогон он получил.
- **BREAKING**: признак `generate_answer` больше не принимается в запросе поиска; запрос с этим полем отклоняется как содержащий неизвестное поле.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `question-search`: требование «Формирование ответа на основе найденных вопросов» переводится на два безусловных прогона генерации — без подгрузки похожих вопросов и с подгрузкой.
- `search-api`: требование «Эндпоинт поиска» фиксирует в структурированном ответе оба сгенерированных ответа вместо одного, а в запросе — отсутствие признака генерации.
- `search-web-ui`: требования «Отображение сгенерированного ответа», «Состав страницы и заголовок интерфейса» и «Форма поиска по описанию вопроса» переводятся на два ответа рядом с подписями; упоминание признака генерации уходит из описания формы.

## Impact

- `src/chgk_agent/search/graph.py` — новая ветка генерации без подгрузки, параллельная поиску, и точка сборки обоих ответов; удаление развилки `needs_generation` и параметра `generate_answer`.
- `src/chgk_agent/search/nodes.py` — узел генерации без подгрузки и разделение промптов; существующий узел генерации продолжает отвечать с подгрузкой; удаление разбора признака и ветвления по нему.
- `src/chgk_agent/search/state.py`, `src/chgk_agent/search/models.py` — два поля ответа вместо одного; удаление признака генерации из состояния.
- `src/chgk_agent/config.py` — удаление настройки `search.generate_answer`.
- `src/chgk_agent/api/schemas.py`, `src/chgk_agent/api/routes.py` — два поля ответа вместо `answer` и удаление признака генерации из запроса (BREAKING для клиентов API).
- `src/chgk_agent/ui/view.py`, `src/chgk_agent/ui/client.py`, `src/chgk_agent/ui/app.py` — модель экрана и разметка с двумя ответами и подписями; клиент больше не передаёт признак генерации.
- `tests/test_search_graph.py`, `tests/test_api.py`, `tests/test_ui.py`, `tests/test_end_to_end.py`, `tests/test_config.py` — проверки двух прогонов, контракта API, отображения и отсутствия удалённой настройки.
- `README.md` — пример ответа API и описание страницы.
