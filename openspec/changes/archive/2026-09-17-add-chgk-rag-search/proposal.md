## Why

Игрокам и редакторам «Что? Где? Когда?» нужен быстрый способ проверить, не задавался ли ранее вопрос, близкий по формулировке или замыслу. Сейчас такой поиск делается вручную: глазами пролистывая HTML-архивы и листая внешний сайт базы вопросов. Ручной просмотр медленный и неполный — легко пропустить дубль из-за перефразировки.

Мы хотим один инструмент, который по текстовому описанию вопроса одновременно ищет похожие вопросы в собственной базе (семантический поиск по эмбеддингам) и во внешней базе ЧГК, объединяет результаты и отдаёт их с оценкой похожести и пояснением от LLM.

## What Changes

- Новый сервис RAG-поиска вопросов ЧГК на GigaChat: семантический поиск по локальной базе (PostgreSQL + pgvector) и параллельный поиск на внешнем сайте базы вопросов, включённый по умолчанию.
- Пайплайн индексации: парсинг HTML-файлов с вопросами и ответами, нормализация, вычисление эмбеддингов через GigaChat, загрузка в pgvector с дедупликацией и версионированием источника.
- Доступ к GigaChat (эмбеддинги и генерация) выполняется через `langchain_gigachat` — официальную интеграцию с LangChain и LangGraph.
- Оркестрация поиска на LangGraph: параллельные ветки локального и внешнего поиска, объединение, дедупликация и ранжирование результатов, опциональная генерация ответа LLM.
- Асинхронный HTTP API на FastAPI: эндпоинты поиска, индексации, job-статуса и health/readiness.
- Веб-интерфейс на NiceGUI: ввод описания вопроса, отображение локальных и внешних совпадений, оценок близости и сгенерированного ответа.
- Наблюдаемость: метрики Prometheus (латентность, объёмы, ошибки по источникам, использование токенов), структурированные JSON-логи и трассировка запросов.
- Тестируемость: асинхронные unit- и integration-тесты с фикстурами БД и заглушками GigaChat/внешнего поиска, целевые метрики качества поиска.

## Capabilities

### New Capabilities
- `question-ingestion`: приём HTML-файлов с вопросами и ответами, парсинг и нормализация в каноническую модель вопроса, вычисление эмбеддингов через GigaChat, идемпотентная загрузка в PostgreSQL + pgvector, дедупликация и учёт версий источника.
- `question-search`: по описанию вопроса параллельно выполняет семантический поиск по локальной базе и поиск по внешнему источнику базы вопросов, объединяет, дедуплицирует и ранжирует результаты, различает пустую выдачу, отвергнутый запрос и недоступность источника, опционально формирует ответ LLM на GigaChat.
- `search-api`: асинхронный FastAPI-слой с эндпоинтами поиска, управления индексацией и служебными проверками, со строгими схемами запросов/ответов и единообразной обработкой ошибок.
- `search-web-ui`: веб-интерфейс на NiceGUI для ввода описания вопроса, отображения сгруппированных результатов поиска, источников, оценок похожести и сгенерированного ответа с отслеживанием состояния запроса.
- `service-observability`: метрики Prometheus, структурированное логирование и трассировка сквозных операций поиска и индексации, включая деградацию внешнего источника и расход токенов GigaChat.

## Impact

- **Код**: новый Python-пакет приложения (API, LangGraph-граф, клиенты GigaChat и внешнего сайта базы вопросов, парсер HTML, репозиторий pgvector, NiceGUI-приложение, CLI-команды индексации).
- **Зависимости**: `python>=3.13`, FastAPI, NiceGUI, LangGraph, `langchain-gigachat`, SQLAlchemy/asyncpg, pgvector, httpx, BeautifulSoup/lxml, pydantic-settings, прометей-клиент, pytest/pytest-asyncio.
- **Инфраструктура**: локально запущенный PostgreSQL с расширением pgvector, переменные окружения для GigaChat (credentials, scope, model) и внешнего источника.
- **Внешние системы**: GigaChat API (эмбеддинги и генерация), `gotquestions.online` (парсинг HTML выдачи; интеграция включена по умолчанию, обязательный осмысленный `User-Agent`, rate limiting и лимит поискового запроса в 50 символов) — оба требуют обработки недоступности и rate limiting.
- **Совместимость**: изменение носит аддитивный характер; существующего поведения в репозитории нет.
