# chgk-agent — RAG-поиск вопросов «Что? Где? Когда?»

Сервис принимает текстовое описание вопроса и одновременно ищет похожие
вопросы в собственной базе (PostgreSQL + pgvector, гибрид векторного и
полнотекстового поиска) и на внешнем сайте базы вопросов
`gotquestions.online`. Совпадения объединяются, дедуплицируются и
ранжируются, после чего по запросу формируется ответ на GigaChat.

## Состав

- `src/chgk_agent/ingestion` — разбор HTML-файлов с вопросами и идемпотентный импорт.
- `src/chgk_agent/embeddings` — эмбеддинги GigaChat, доиндексация очереди невекторизованных вопросов.
- `src/chgk_agent/search` — гибридный локальный поиск, внешний источник, граф поиска на LangGraph.
- `src/chgk_agent/api` — HTTP API на FastAPI.
- `src/chgk_agent/ui` — веб-интерфейс на NiceGUI, смонтированный в то же приложение.
- `openspec/specs` — действующие спецификации поведения, `openspec/changes/archive` — история изменений.

## Требования

- Python 3.13 и [uv](https://docs.astral.sh/uv/).
- Локальный PostgreSQL с расширением [pgvector](https://github.com/pgvector/pgvector).
- Доступ к GigaChat API (credentials, scope) для эмбеддингов и генерации.

## Локальный запуск

1. Установить зависимости:

   ```bash
   uv sync
   ```

2. Убедиться, что PostgreSQL с pgvector запущен и создать базу:

   ```bash
   pg_isready -h localhost -p 5432
   createdb -h localhost -p 5432 chgk_agent
   ```

   Если расширения `vector` в кластере нет, его нужно установить
   (`brew install pgvector` или пакет для вашей платформы): миграция
   выполняет `CREATE EXTENSION IF NOT EXISTS vector`.

3. Скопировать `.env.example` в `.env` и заполнить значения — как минимум
   `CHGK_DATABASE__DSN` и `CHGK_GIGACHAT__CREDENTIALS`. Пример:

   ```bash
   cp .env.example .env
   ```

4. Применить миграции:

   ```bash
   uv run alembic upgrade head
   ```

5. Запустить сервис (API и веб-интерфейс в одном процессе):

   ```bash
   uv run chgk-serve
   # то же самое: uv run python main.py
   ```

   Интерфейс — `http://localhost:8000/ui/`, документация API —
   `http://localhost:8000/docs`.

   Интерфейс смонтирован только при запуске через `chgk-serve`; другие
   способы запуска ASGI-приложения отдают API без страниц `/ui`.

6. Проверить готовность:

   ```bash
   curl -s http://localhost:8000/healthz
   curl -s http://localhost:8000/readyz
   ```

   `/readyz` отвечает `200`, когда база данных доступна и внешний источник
   отвечает статусом `ok` или `empty` (не `rejected` и не `unavailable`).
   При недоступной зависимости он отвечает `503` и перечисляет её в
   `dependencies`.

## Загрузка вопросов

Источники — экспорт Telegram-чата с вопросами в HTML. Личные экспорты
лежат в `resources/` и намеренно не попадают в git, поэтому подставьте
имя своего файла вместо `<экспорт>.html`.

Разобрать HTML-файлы без записи в базу:

```bash
uv run chgk-parse <экспорт>.html --show-questions 3
```

Запустить импорт с записью в базу, дедупликацией и векторизацией:

```bash
uv run chgk-import <экспорт>.html
uv run chgk-import <экспорт>.html --skip-embeddings   # без GigaChat
```

Через API импорт запускается асинхронно:

```bash
curl -s -X POST http://localhost:8000/imports \
  -H 'Content-Type: application/json' \
  -d '{"paths": ["<экспорт>.html"]}'
curl -s http://localhost:8000/imports/<operation_id>
```

## Поиск

Через API:

```bash
curl -s -X POST http://localhost:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query": "английский учёный давал клички лабораторным животным", "limit": 5}'
```

Веб-интерфейс доступен по адресу `http://localhost:8000/ui/`.

## Внешний источник gotquestions.online

- **Интеграция включена по умолчанию** (`CHGK_EXTERNAL__ENABLED=true`) и
  опрашивается параллельно с локальной базой.
- **Обязателен осмысленный `User-Agent`.** Сайт отвечает `403` на
  стандартный `curl`; значение по умолчанию указывает на сервис. Задайте
  свой контакт в `CHGK_EXTERNAL__USER_AGENT`, чтобы администрация сайта
  могла связаться с вами.
- **Жёсткий лимит 50 символов на поисковый запрос.** Более длинный запрос
  сайт молча отклоняет, поэтому длинное описание автоматически сокращается
  до одного или нескольких коротких запросов из ключевых терминов. Локальный
  поиск при этом получает полное описание.
- **Ограничение частоты запросов** — `CHGK_EXTERNAL__MIN_INTERVAL_SECONDS`
  (по умолчанию `1.0`) задаёт минимальную паузу между обращениями к сайту.
- **Разметка неофициальная.** Парсер различает четыре исхода: `ok`
  (непустая выдача), `empty` («Ничего не найдено»), `rejected` (страница без
  блока результатов, типично при превышении лимита) и `unavailable` (сеть,
  таймаут, `403`, `5xx`). При `rejected` или `unavailable` поиск продолжает
  отдавать локальные совпадения и помечает ответ частичным.
- **`robots.txt`.** Правила сайта закрывают `/search` (`Disallow: /search`).
  Владелец сервиса принял решение работать с этой страницей, ограничившись
  rate limiting, поэтому по умолчанию правила не применяются. Строгий режим
  включается флагом `CHGK_EXTERNAL__RESPECT_ROBOTS=true`: тогда страница
  поиска не запрашивается, а ветка возвращает `unavailable`.
- **Отключение.** `CHGK_EXTERNAL__ENABLED=false` полностью выключает
  внешнюю ветку: запросы к сайту не выполняются, а поиск возвращает только
  локальные совпадения. Это же значение используйте для отката, если
  разметка сайта изменилась.

## Конфигурация

Все настройки читаются из переменных окружения с префиксом `CHGK_` и
вложенностью через `__` (см. `.env.example`):

- `CHGK_DATABASE__DSN` — DSN PostgreSQL с драйвером `asyncpg`.
- `CHGK_DATABASE__TEST_DSN` — DSN базы для интеграционных тестов;
  по умолчанию рабочая база с суффиксом `_test`.
- `CHGK_GIGACHAT__*` — credentials, scope, модели и размерность эмбеддинга.
- `CHGK_EXTERNAL__*` — внешний источник: включение, `user_agent`, лимиты,
  таймауты, rate limiting и `respect_robots`.
- `CHGK_SEARCH__*` — число результатов, порог, таймауты веток, включение
  полнотекстовой ветки и генерации ответа.
- `CHGK_OBSERVABILITY__*` — уровень логов и формат JSON.

## Смена модели эмбеддингов

Размерность вектора задаётся настройкой `CHGK_GIGACHAT__EMBEDDING_DIM`, а
колонка `questions.embedding` создаётся как `vector(<embedding_dim>)`. При
старте сервис сверяет тип колонки с настройкой и падает с понятной ошибкой,
если миграция под новую размерность не применена. При смене модели:

1. Обновите `CHGK_GIGACHAT__EMBEDDING_MODEL` и `CHGK_GIGACHAT__EMBEDDING_DIM`.
2. Приведите схему к новой размерности. Полный сброс
   (`uv run alembic downgrade base && uv run alembic upgrade head`) удаляет
   таблицы `questions` и `sources` вместе со всеми импортированными вопросами:
   после него потребуется повторный импорт HTML-файлов. Если данные нужно
   сохранить, примените миграцию, меняющую тип колонки `questions.embedding`.
3. Запустите переиндексацию — она считает эмбеддинги заново, не переразбирая
   HTML:

   ```bash
   uv run chgk-reindex
   ```

   Команда обрабатывает вопросы без эмбеддинга и вопросы, векторы которых
   посчитаны другой моделью или размерностью, поэтому после смены модели
   достаточно обычного запуска — он не трогает актуальные векторы.

   Для полного пересчёта, включая векторы текущей модели, добавьте `--force`:
   команда пройдёт по всем вопросам ровно один раз. Это нужно, если вектор
   испорчен, но формально совпадает с настройкой.

   ```bash
   uv run chgk-reindex --force
   ```

   Ограничения по источнику у команды нет: выбор одного файла не поддерживается,
   потому что свежеимпортированные вопросы векторизуются самим импортом.

## Качество поиска

Базовые метрики (`recall@k`, `MRR`) измеряются на наборе
«описание → ожидаемый вопрос» и сохраняются отчётом-артефактом:

```bash
uv run chgk-eval
uv run chgk-eval --cases resources/search_quality_cases.json \
  --output resources/search_quality_report.json --k 5
```

Отчёт содержит агрегаты и ранг каждого случая, поэтому изменения
ранжирования или модели эмбеддингов можно сравнивать между собой.

## Тесты и линтер

```bash
uv run pytest -q
uv run ruff check src tests
```

Интеграционные тесты помечены маркером `integration` и работают на
отдельной базе, чтобы не изменять рабочую. Её адрес берётся из
`CHGK_DATABASE__TEST_DSN`, по умолчанию — рабочая база с суффиксом `_test`
(`chgk_agent` → `chgk_agent_test`). База создаётся автоматически, схема
доводится до актуальной миграциями Alembic, поэтому дополнительных шагов
не требуется; нужен только локальный PostgreSQL с pgvector и право
`CREATEDB`. Если создать базу нельзя, интеграционные тесты пропускаются с
подсказкой, а модульные выполняются как обычно. Рабочая база из `CHGK_DATABASE__DSN`
тестами не читается и не изменяется: запуск остановится с ошибкой, если
адреса совпадут.

## Наблюдаемость

- `GET /metrics` — метрики Prometheus: операции поиска по источникам и
  статусам, пустые и отвергнутые внешние выдачи, сокращённые запросы,
  индексация, размер очереди невекторизованных вопросов, использование
  GigaChat (вызовы, ошибки, токены).
- Логи структурированные (JSON при `CHGK_OBSERVABILITY__JSON_LOGS=true`) и
  содержат `request_id`, операцию, статус, длительность и источники;
  секреты маскируются.
- Каждый запрос получает сквозной `X-Request-ID` (или принимает входящий),
  который возвращается в ответах и попадает в логи и конверт ошибок.
- Операции импорта связаны идентификатором: он есть в отчёте, логах и
  доступен через `GET /imports/{operation_id}`.
