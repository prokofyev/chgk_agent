# chgk-agent — RAG-поиск вопросов «Что? Где? Когда?»

Сервис принимает текстовое описание вопроса и параллельно ищет похожие вопросы
в собственной базе (PostgreSQL + pgvector, гибрид векторного поиска и BM25 по
точным словам) и на внешнем сайте `gotquestions.online`. Найденные вопросы
служат подсказкой GigaChat, которая отвечает на исходный вопрос; если ответ
получить не удалось, интерфейс отвечает «Не знаю».

## Состав

- `src/chgk_agent/ingestion` — разбор HTML-файлов с вопросами и идемпотентный импорт.
- `src/chgk_agent/embeddings` — эмбеддинги GigaChat, доиндексация очереди невекторизованных вопросов.
- `src/chgk_agent/search` — гибридный локальный поиск, внешний источник, граф поиска на LangGraph.
- `src/chgk_agent/api` — HTTP API на FastAPI.
- `src/chgk_agent/ui` — веб-интерфейс на NiceGUI, смонтированный в то же приложение.

## Требования

- Python 3.13 и [uv](https://docs.astral.sh/uv/).
- Локальный PostgreSQL с расширением [pgvector](https://github.com/pgvector/pgvector).
- Доступ к GigaChat API (credentials, scope) для эмбеддингов и генерации.

## Локальный запуск

1. Установить зависимости:

   ```bash
   uv sync
   ```

2. Убедиться, что PostgreSQL с pgvector запущен и создать базу:

   ```bash
   pg_isready -h localhost -p 5432
   createdb -h localhost -p 5432 chgk_agent
   ```

   Если расширения `vector` в кластере нет, его нужно установить
   (`brew install pgvector` или пакет для вашей платформы): миграция
   выполняет `CREATE EXTENSION IF NOT EXISTS vector`.

3. Скопировать `.env.example` в `.env` и заполнить значения — как минимум
   `CHGK_DATABASE__DSN` и `CHGK_GIGACHAT__CREDENTIALS`:

   ```bash
   cp .env.example .env
   ```

4. Применить миграции:

   ```bash
   uv run alembic upgrade head
   ```

5. Запустить сервис (API и веб-интерфейс в одном процессе):

   ```bash
   uv run chgk-serve
   ```

   Интерфейс — `http://localhost:8000/ui/`, документация API —
   `http://localhost:8000/docs`.

   Перезапуск при изменении исходников включается только флагом `--reload`
   (по умолчанию он выключен). Интерфейс смонтирован только при запуске через
   `chgk-serve`; другие способы запуска ASGI-приложения отдают API без
   страниц `/ui`.

6. Проверить готовность:

   ```bash
   curl -s http://localhost:8000/healthz
   curl -s http://localhost:8000/readyz
   ```

   `/readyz` отвечает `200`, когда база данных доступна и внешний источник
   отвечает статусом `ok` или `empty`; при недоступной зависимости — `503`
   с её перечислением в `dependencies`.

## Загрузка вопросов

Источники — экспорт Telegram-чата с вопросами в HTML.

```bash
uv run chgk-parse <экспорт>.html --show-questions 3   # разбор без записи в базу
uv run chgk-import <экспорт>.html                     # импорт, дедупликация, векторизация
uv run chgk-import <экспорт>.html --skip-embeddings   # без GigaChat
```

Через API импорт запускается асинхронно:

```bash
curl -s -X POST http://localhost:8000/imports \
  -H 'Content-Type: application/json' \
  -d '{"paths": ["<экспорт>.html"]}'
curl -s http://localhost:8000/imports/<operation_id>
```

## Поиск

```bash
curl -s -X POST http://localhost:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query": "английский учёный давал клички лабораторным животным", "limit": 5}'
```

Ответ содержит два независимых прогона генерации: `answer_without_context` —
модель отвечает сама, и `answer_with_context` — с найденными вопросами как
подсказкой. Если совпадений выше порога нет, второй прогон не выполняется, и
`answer_with_context` равно `null`. Отключить генерацию в запросе нельзя.

Веб-интерфейс (`/ui/`) содержит поле «Описание вопроса», кнопку «Ответить» и
два ответа под подписями «Без базы вопросов» и «С учётом базы вопросов».
Кнопка заблокирована, пока описание короче трёх символов.

Оценка близости одна для обоих источников:
`score = косинус(описание, «вопрос + ответ») + вес * BM25(описание, «вопрос + ответ»)`.

## Внешний источник gotquestions.online

Интеграция включена по умолчанию (`CHGK_EXTERNAL__ENABLED=true`). Особенности
эксплуатации:

- Поисковый запрос ограничен 50 символами, поэтому длинное описание
  сокращается до нескольких коротких запросов из ключевых терминов; локальный
  поиск получает полное описание.

## Конфигурация

Настройки читаются из переменных окружения с префиксом `CHGK_` и вложенностью
через `__` (см. `.env.example`):

- `CHGK_DATABASE__DSN` — DSN PostgreSQL с драйвером `asyncpg`.
- `CHGK_DATABASE__TEST_DSN` — DSN базы для интеграционных тестов.
- `CHGK_GIGACHAT__*` — credentials, scope, модели и размерность эмбеддинга.
- `CHGK_EXTERNAL__*` — включение, `user_agent`, лимиты, таймауты, rate limiting.
- `CHGK_SEARCH__*` — число результатов, порог отбора контекста, таймауты
  веток, вес и насыщение лексического сигнала.
- `CHGK_OBSERVABILITY__*` — уровень логов и формат JSON.

## Тесты и линтер

```bash
uv run pytest -q
uv run ruff check src tests
```

Интеграционные тесты помечены маркером `integration` и работают на отдельной
базе из `CHGK_DATABASE__TEST_DSN` (по умолчанию рабочая база с суффиксом
`_test`). База создаётся автоматически, схема доводится миграциями Alembic;
нужен локальный PostgreSQL с pgvector и право `CREATEDB`. Если создать базу
нельзя, интеграционные тесты пропускаются, а модульные выполняются как обычно.
Совпадение адресов рабочей и тестовой базы останавливает запуск с ошибкой.

## Наблюдаемость

- `GET /metrics` — метрики Prometheus: операции поиска по источникам и
  статусам, исходы внешней выдачи, деградация лексической ветки, индексация,
  очередь невекторизованных вопросов, использование GigaChat.
- Логи структурированные (JSON при `CHGK_OBSERVABILITY__JSON_LOGS=true`),
  содержат `request_id`, операцию, статус, длительность и источники; секреты
  маскируются.
- Каждый запрос получает сквозной `X-Request-ID` (или принимает входящий),
  который возвращается в ответах и попадает в логи и конверт ошибок.
- Операции импорта связаны идентификатором: он есть в отчёте, логах и доступен
  через `GET /imports/{operation_id}`.
